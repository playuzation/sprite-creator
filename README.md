# sprite-creator

브라우저에서 동작하는 픽셀 스프라이트 제작 도구입니다.
`main` 브랜치에 반영되면 GitHub Pages(https://playuzation.github.io/sprite-creator/)로 배포됩니다.

## 기능

- **캔버스**: 기본 128×128, 1~1024 사이 크기 지원
  - 해상도 변경: 모든 프레임·레이어의 그림을 늘리거나 줄여 크기·비율을 바꿈. 팔레트 색이 섞이지 않도록 가장 가까운 픽셀을 가져옴(최근접 이웃). '비율 유지'로 한쪽만 바꿀 수 있음
  - 캔버스 변경: 그림은 그대로 두고, 늘리면 투명하게 채우고 줄이면 잘라냄. 기준은 가운데와 8방향(위·아래·왼쪽·오른쪽·네 모서리) 중 선택
  - 두 경우 모두 벡터 도형·패스도 그림에 맞춰 옮겨지고(해상도 변경은 도형의 선 두께도 함께 바뀜), 선택 영역은 해제됨
- **팔레트**: 스프라이트마다 최대 32색. 각 픽셀은 팔레트 색 중 하나이거나 투명(빈 배경)
- **레이어**: 픽셀 레이어('추가')와 벡터 레이어('벡터 추가'). 삭제, 이름 변경, 순서 변경, 보이기/숨기기
- **타임라인**: 프레임을 추가하면 현재 프레임의 모든 레이어(픽셀과 벡터 도형)가 복사되어, 프레임마다 조금씩 수정 가능. 재생 및 FPS 설정
- **도구**: 연필, 지우개, 채우기, 확대/축소
- **선택 도구**: 끌어서 직사각형 영역을 선택하면 연필·지우개·채우기·벡터가 그 안의 픽셀에만 적용됨 (채우기는 선택 경계를 넘지 않음). 선택 영역 밖을 클릭하거나 '선택 해제'로 해제
  - 이동: 선택 영역 안을 끌거나 방향키로 현재 레이어의 그 픽셀을 옮김. 원래 자리는 투명해지고, 다른 그림 위에 놓았다가 다시 옮겨도 그 아래 그림은 되살아남
  - 복사·붙여넣기: 현재 레이어의 선택 영역 픽셀을 복사해, 복사한 위치에 붙임 (다른 프레임·레이어에도 가능). 붙인 뒤 바로 끌어 옮길 수 있음
- **벡터 도구 (픽셀 레이어)**: 클릭으로 점을 찍어 패스를 만들고(점을 끌어 위치 조정), '패스 그리기'로 현재 레이어에 픽셀을 렌더링. 패스는 그린 뒤에도 남아 다른 프레임·레이어에 다시 그릴 수 있고, 프로젝트 파일에 함께 저장됨
  - 곡선: 찍은 점을 모두 지나는 부드러운 곡선(캣멀-롬)으로 그림
  - 두께: 1~32픽셀
  - 안티에일리어싱: 픽셀은 팔레트 색만 가질 수 있으므로, 선이 걸친 비율만큼 선 색과 아래에 보이는 색을 섞은 색을 두 색 사이에 있는 팔레트 색으로 칠함. 사이 색이 없으면 둘 중 하나가 되고, 아래가 투명한 픽셀은 절반 이상 걸칠 때만 칠함
- **벡터 레이어**: 벡터 도구로 그린 도형(점·곡선·두께·안티에일리어싱·색)을 픽셀로 굽지 않고 보관해 언제든 고칠 수 있음. 화면과 PNG·GIF 등 이미지에는 픽셀로 그려지고(안티에일리어싱은 그 아래에 보이는 그림과 섞음), 프레임마다 따로 가짐
  - 빈 곳 클릭: 새 도형을 시작하거나 편집 중인 도형에 점을 이어 찍음 (점 하나뿐이면 점으로 그려짐). 점을 끌어 위치 조정
  - 선 클릭: 그 도형을 골라 다시 편집. 곡선·두께·안티에일리어싱을 바꾸거나 팔레트 색을 눌러 도형 색을 바꿈 (편집 중이 아니면 이 설정은 새 도형의 기본값)
  - '도형 완료'(Enter·Esc)로 편집을 마치고, '도형 삭제'(Delete)로 지움
  - 연필·지우개·채우기와 선택 영역 픽셀 이동·복사·붙여넣기는 픽셀 레이어에서만 됨 (벡터 레이어에서는 커서가 금지 표시)
  - 팔레트에서 색을 지우면 그 색의 도형도 지워짐
- **화면 이동**: 스페이스바를 누른 채 드래그(데스크톱), 두 손가락으로 드래그(모바일)
- **저장/불러오기**: 프로젝트 파일(JSON) 다운로드/업로드
- **내보내기**: 형식을 고르고 '내보내기' (투명 배경, 애니메이션은 무한 반복)
  - 현재 프레임 이미지: PNG, JPG(투명도를 담지 못해 흰 배경), WebP(무손실), AVIF, SVG
  - SVG는 보이는 레이어가 모두 벡터 레이어일 때 고를 수 있으며, 도형을 벡터 그대로 담아 확대해도 매끄러움. 안티에일리어싱을 끈 도형은 가장자리를 부드럽게 하지 않음(`crispEdges`). 팔레트 색으로 섞는 화면의 픽셀 그림과 달리 안티에일리어싱은 SVG를 보는 프로그램이 함
  - 애니메이션(모든 프레임): GIF, WebP(무손실), AVIF
  - AVIF는 브라우저의 AV1 인코더(WebCodecs)로 만들어 Chrome·Edge처럼 AV1 인코딩을 지원하는 브라우저에서만 됩니다. 가장 높은 품질로 압축하지만 완전한 무손실은 아니어서 색·투명도 값이 1 정도 달라질 수 있습니다(눈으로는 구분되지 않음)

## 단축키

| 키 | 동작 |
|---|---|
| B / E / G / M / P | 연필 / 지우개 / 채우기 / 선택 / 벡터 |
| Ctrl(⌘)+C / Ctrl(⌘)+V | 선택 영역 복사 / 붙여넣기 |
| Ctrl(⌘)+A | 전체 선택 |
| Ctrl(⌘)+S | 프로젝트 저장 |
| 방향키 (Shift: 10픽셀) | 선택 영역 픽셀 이동 |
| Esc | 도형 완료(벡터 레이어에서 도형 편집 중일 때), 패스 지우기(픽셀 레이어의 벡터 도구에서 점이 있을 때), 그 밖에는 선택 해제 |
| Enter | 패스 그리기 (픽셀 레이어의 벡터 도구), 도형 완료 (벡터 레이어) |
| Delete / Backspace | 편집 중인 도형 삭제 (벡터 레이어) |
| 스페이스바 + 드래그 | 화면 이동 |

## 프로젝트 파일 형식 (JSON, version 1)

```json
{
  "format": "sprite-creator",
  "version": 1,
  "width": 128,
  "height": 128,
  "fps": 10,
  "palette": ["#140c1c", "#442434"],
  "layers": [{ "name": "레이어 1", "visible": true, "kind": "pixel" }, { "name": "레이어 2", "visible": true, "kind": "vector" }],
  "frames": [
    {
      "cels": ["eJzt...", "eJzt..."],
      "shapes": [[], [{ "points": [{ "x": 3, "y": 4.5 }, { "x": 30, "y": 9 }], "curve": true, "width": 2, "antialias": true, "color": 7 }]]
    }
  ],
  "path": { "points": [{ "x": 10.5, "y": 20.5 }], "curve": false, "width": 1, "antialias": false }
}
```

- `layers[l].kind`: `"pixel"`(픽셀 레이어) 또는 `"vector"`(벡터 레이어). 없는 예전 파일은 픽셀 레이어로 읽습니다.
- `frames[f].cels[l]`: f번째 프레임에서 l번째 레이어(0이 맨 아래)의 픽셀입니다.
  행 우선, 픽셀당 1바이트(0 = 투명, n = `palette[n - 1]`)를 zlib(deflate)로 압축한 뒤 base64로 담습니다. 벡터 레이어는 쓰지 않아 비어(투명) 있습니다.
- `frames[f].shapes[l]`: 벡터 레이어의 도형들(앞쪽부터 그림)입니다. 점(픽셀 좌표, 소수 가능, 1개 이상)과 곡선·두께(1~32)·안티에일리어싱, 색 `color`(픽셀 값처럼 n = `palette[n - 1]`)를 담고, 픽셀 레이어는 빈 목록입니다. 없는 예전 파일은 도형이 없는 것으로 읽습니다.
- `path`: 벡터 도구의 패스(픽셀 좌표, 소수 가능)와 곡선·두께(1~32)·안티에일리어싱 설정입니다. 없는 예전 파일은 빈 패스로 읽습니다.

## 개발

```sh
npm ci
npm run dev     # 로컬 개발 서버
npm test        # 단위 테스트
npm run build   # 타입 검사 + dist/ 빌드
```

## 배포

- `main`에 push되면 `.github/workflows/deploy-pages.yml`이 테스트·빌드 후 GitHub Pages에 배포합니다.
- 최초 1회 설정이 필요합니다: 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택.

## 브랜치 규칙

- 코드를 수정하면 `feat/…`, 텍스트 파일만 수정하면 `docs/…` 브랜치에서 작업합니다.
- 작업 브랜치는 `dev`로 PR을 만들어 머지합니다. `main`에는 요청이 있을 때 `dev` → `main` PR로 반영합니다.
- 머지된 작업 브랜치는 `.github/workflows/delete-merged-branch.yml`이 자동으로 삭제합니다 (`dev`, `main` 제외).

## 구조

의존 방향은 위에서 아래로만 흐르는 트리입니다.

```
src/main.ts      진입점
└─ ui/           DOM 편집기 (패널, 편집 상태 저장소)
   └─ sprite/    스프라이트 도메인: 모델, 그리기, 합성, 저장/불러오기, 이미지 내보내기 (DOM 없음)
      └─ codec/  범용 인코딩: GIF89a, WebP(VP8L), AVIF(컨테이너 + WebCodecs AV1), deflate, base64 (스프라이트를 모름)
```

각 패키지는 바로 아래 패키지의 `index.ts`만 import합니다.
`tests/architecture.test.ts`가 역방향 의존, `index.ts` 우회, 순환 참조를 검사합니다.
